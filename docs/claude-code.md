# Claude Code で開発するとき

このリポジトリを Claude Code で開いて作業するときの仕組みと、踏んだことをまとめた。
Bend そのものの話は [language.md](language.md) と [proofs.md](proofs.md) にある。

特に断りのない記述は、実際に動かして確かめたこと。ガイドなどの記述だけに基づくものには「（文書のみ）」、
確かめていないものには「（未確認）」と書いた。

## 2 つのフックが、Bend の導入と証明の検査を自動にしている

どちらも `.claude/settings.json` に登録してある。

| フック | 動くとき | すること |
|---|---|---|
| `.claude/hooks/session-start.sh` | クラウド環境でセッションを始めたとき | Bend 2.0.34 と Lean 4.34.0 を入れ、PATH を通す |
| `.claude/hooks/bend-check.sh` | `.bend` ファイルを Write・Edit したとき | `bend --check-only` で検査し、失敗したら Claude に差し戻す |

フックが使われるのは、リポジトリの既定のブランチに入ってからのセッションだけ。

### セッション開始のフック: クラウド環境で、版を固定して導入する

クラウド環境（環境変数 `CLAUDE_CODE_REMOTE=true`）でだけ動き、それ以外では何もせずに終わる。
クラウドのコンテナは回収されると `~/.bend`・`~/.elan` が消えるので、セッションのたびに入れ直す必要がある。そのためのフック。

1. Bend 2.0.34 を入れる。公式インストーラは最新版を入れるので使わず、同じ手順（tarball の取得、SHA256 の照合、`~/.bend` への配置）を
   フックの中で行う。SHA256 が合わなければ何も置かずに終了コード 1 で止まる。
2. clang が無ければ警告だけ出す。
3. elan で Lean v4.34.0 を入れる。
4. 小さな証明に `--verdict` を 1 回かけ、カーネルを先に作っておく。
5. PATH と `BEND_NO_TELEMETRY=1` を `CLAUDE_ENV_FILE` に書き、以後のコマンドに効かせる。

どの段階も「入っていれば飛ばす」ので、何度動かしても同じ状態になる。何も入っていない状態から 54 秒、入っている状態なら 0.2 秒未満で終わった。
新しいセッションで試すと、追加の設定なしで `bend PROOF.bend --verdict` が 0.59 秒で通った。

ディスクは Lean だけで約 3 GB 使う。クラウド環境ではフックが終わった後の状態がキャッシュされるとされるが（文書のみ）、
新しいセッションで実際に何秒かかるかは測っていない。

### 編集後のフック: `.bend` を直すたびに証明を検査する

`.bend` ファイルが変わったときだけ動く。編集したファイルを `bend <ファイル> --check-only` で検査し、同じフォルダに `PROOF.bend` があれば
それも検査する。本体の変更で証明が壊れたことに、その場で気づける。`LAWS.bend` を直したときは、単体では必ず失敗するので
`PROOF.bend` だけを検査する。

失敗したときは、出力の先頭 25 行（1 行 400 文字まで）を Claude に返し、直させる。成功したときは何も出さない。
1 回の検査は、クラウド環境で 0.2〜0.6 秒、Windows で 1〜2 秒ほど。

bend の動かし方は環境で変わる。

- **bend が PATH にある（クラウド環境）**: そのまま使う。
- **bend が無く wslc がある（Windows）**: `container/Containerfile` から作ったイメージの中で検査する。既定のイメージ名は `bend2-slim` で、
  環境変数 `BEND_CHECK_IMAGE` で変えられる。イメージが無ければ、作り方を知らせて何もしない。
- **どちらも無い**: 知らせて何もしない。

入力の JSON は jq で読み、jq が無ければ Python で読む。Windows の Git Bash には jq が無く、以前の版はこのせいで、知らせも出さずに
何もしていなかった。

## フックが動かないときに確かめること

- **フックを登録したそのセッション**: 登録した後に Edit しても動かなかった。セッションを始めた場所に `.claude/settings.json` が
  無かったためと考えられる（設定の見張りは、開始時に設定ファイルがあった場所だけが対象）。`/hooks` を一度開くか、セッションを始め直す。
- **Windows**: `wslc image list` に `bend2-slim` があるかを見る。無ければ README の手順で作る。

## クラウド環境の癖

- **リモートのブランチは消せない。** `git push origin --delete <ブランチ>` は HTTP 403 で断られた（通常の push は通る）。
  消すときは GitHub の画面で行う。
- **アプリから開けるのは `/home/user` の下だけ。** `~`（= `/root`）に置いたファイルは見えない。成果物は `/home/user` に置く。
- **新しいセッションでの挙動は、別のセッションに試させて確かめられる。** 別のクラウドセッションを立てて作業させ、
  結果をブランチに push させて読む。上の 2 つのフックはこの方法で確かめた。

## 記録を足すときの決まり

分かったことは、読む人に合わせて `docs/` のどれかに足す。Bend の書き方は language.md、証明は proofs.md、
環境は environments.md、Claude Code まわりはこの文書。

特に断りのない記述は「実際に動かして確かめたこと」として読まれる。ガイドなどの記述だけに基づくものには「（文書のみ）」、
確かめていないものには「（未確認）」と書く。外部の資料を使ったら、URL と、本文を読んだか抜粋だけかを添える。
依頼者の手元の環境の情報（ローカルのパス、ドライブ名など）は書かない。

## これから作るとよさそうなもの

- **commit の前の検査**: ファイルの移動のように Edit を通らない変更では、編集後のフックが動かない。commit の前に
  `PROOF.bend --check-only` を走らせれば、ここが埋まる。
- **スキル「Bend の証明」**: proofs.md の「証明を書くときのこつ」と「毎回ここまで確かめる」を手順にしたもの。
- **スキル「Bend のサーバーと入出力」**: language.md の入出力と C まわりの落とし穴。

## 付録: フックの確かめ方と結果

入力の JSON を直接流して確かめた。

| 入力 | クラウド環境 | Windows（jq なし、wslc あり） |
|---|---|---|
| 正常な `server.bend` | 出力なし | 出力なし（約 2.3 秒） |
| `LAWS.bend` | `PROOF.bend` に振り替えて通過 | 同じ（約 1.3 秒） |
| `.bend` 以外 | 何もしない | 何もしない |
| `/hello/` の切り取りを 6 文字にした `server.bend` | `PROOF.bend` の期待値の不一致で差し戻す | 同じ |
| 未定義の名前を使うファイル | `expected : a defined name` で差し戻す | （試していない） |
| bend も wslc も無い、またはイメージが無い | 知らせるだけ | 知らせるだけ |
| PATH に `bend` がある | ― | wslc ではなくその bend を使う |
| 空白を含む場所にリポジトリがある | ― | 起動する（`settings.json` のパスを引用符で囲んである） |

実際のセッションでも、Edit で `server.bend` の `7n` を `6n` にすると、`Laws.hello_echo` の期待値の不一致で差し戻された
（クラウド環境と Windows の両方）。戻す Edit では何も出なかった。

## 付録: スライドの PDF 化（`docs/bend2-spike-slides.pdf`）

- Playwright の Chromium は、クラウド環境で Google Fonts を読み込めなかった（`document.fonts` が空。プロキシを指定しても同じ）。
  CSS と woff2 を curl で落とし、手元の `@font-face` にすると読み込めた。CSS の中の `url()` は、CSS ファイルからの相対パスになる。
- JetBrains Mono は合字で `++` や `==` を 1 つの記号にして描くので、Bend のコードが別物に見える。合字の無い IBM Plex Mono に替えた。
